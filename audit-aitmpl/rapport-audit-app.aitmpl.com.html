01Verdict

Le contenu est au niveau, la couche d'interaction ne l'est pas. La fiche composant est excellente, le design system est solide, mais les deux systèmes de recherche ne donnent pas les mêmes résultats, les filtres et le tri se désynchronisent de l'état réel, la pagination perd l'utilisateur et trois pages majeures sont vides sans JavaScript.

03Constats structurants

Les quatre problèmes de fond, illustrés.

S1FX-01

Deux moteurs de recherche, deux qualités

Dans la palette ⌘K : « frontend design » → No results found (le composant existe, il est n°1 de l'accueil). « react » → Shopify Expert, Web3 Integration Specialist, Communication Excellence Coach. La recherche inline des pages de liste, elle, trouve correctement. C'est le premier point de friction du produit.

S2LI-01 / LI-02

Des contrôles qui ne partagent pas leur état

Chip creative-design active → select toujours sur « All categories ». Select sur database → chip grise. Tri alphabétique → select revenu sur « Most Popular ». Trois contrôles, trois états parallèles pour la même vérité.

S2LI-06

Trois squelettes de navigation

Header global présent sur l'accueil et les listes, absent sur les fiches et /my-components. Sidebar enrichie de Docs/GitHub sur les fiches. Rail sponsorisé uniquement sur l'accueil. Cinq motifs de hero différents.

S2FX-05 / PERF-01

Contenu non servi, contenu trop servi

Trois pages renvoient une coquille de 54 Ko sans h1 ni données. À l'inverse, /jobs rend 902 cartes d'un coup : 25 447 nœuds DOM, 2 392 SVG, load à 7,5 s.

05Plan d'action en trois sprints

1 · Rendre la recherche et les filtres fiables

  • Un seul index, un seul ranking, nombre de résultats affiché
  • Recherche et tri réintroduits en mobile
  • Un seul état filtre/tri, 30 catégories accessibles
  • Recherche, catégorie, tri et page dans l'URL

2 · Navigation et feedback

  • scrollTo(0) au changement de page, pagination numérotée
  • Toasts + aria-live pour copie, save, filtres, stack
  • Confirmation sur « Add Page to Stack »
  • Palette et tiroir conformes (dialog, focus trap, Esc)

3 · Cohérence et accessibilité

  • Accent assombri pour le texte (#b65b3c ≈ 4,6:1)
  • Jamais de opacity:0 focusable
  • Labels sur les 3 champs et le slider
  • Tokens danger/warning/info, carte et modale uniques

Chantier de fond · Shell unique

  • Un layout partagé par toutes les pages
  • SSR pour /jobs, /certifications, /trending
  • URL par offre + pagination serveur sur /jobs
  • Thème Clerk synchronisé avec le thème de l'app

06Limites

Parcours authentifié non couvert (aucun compte disponible) : My Components, sauvegarde de stacks et collections, déblocage des offres et certifications, onboarding post-connexion.

Non testé : API (/api/spot, /openapi.json), Safari/Firefox, lecteurs d'écran réels (NVDA, VoiceOver), réseau dégradé, charge. Les mesures de performance viennent d'une session unique : les valeurs absolues sont indicatives, les écarts structurels (25 k nœuds sur /jobs, 1,35 Mo de HTML sur /plugins) sont fiables.
